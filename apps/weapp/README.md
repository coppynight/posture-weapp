# posture-miniprogram

WeChat mini program for a guest posture check. The guest shoots or picks a **front** photo on one screen, then a **side** photo on the next screen. The side screen calls the T2 API `POST /v1/analyze`. A successful response opens a Simplified Chinese training report. A quality or missing-photo response stays on the capture flow with retake guidance.

The mini program does not score posture itself. It does not log the guest in, it does not keep a history list, and it does not write photos or reports to local storage.

The report is one scrolling page: **总览**, then **问题**, then **动作**. The disclaimer is the first block of the overview card. Cause guesses sit inside the matching problem card. The share card uses those same three section names.

From the report page the guest can save a share card. That path is **save to album** (`wx.saveImageToPhotosAlbum`). The card is a 750×1334 PNG drawn from the in-memory report: overview, the main problem, exercise tips, and the **非医疗诊断** disclaimer. It does not include the selfies. The mini program card share stays hidden, because a shared page would open an empty visit for the recipient. After the album write, the temp PNG is deleted. The guest forwards the album image in WeChat.

## Layout

| Path | Role |
| --- | --- |
| `src/` | Session, submit guard, T2 client, and view models. Tested in Node. |
| `miniprogram/lib/` | CommonJS build of `src/`, loaded by the mini program. Regenerated by `npm run build`. |
| `miniprogram/pages/capture/` | Front step, then side step. One photo slot on screen. |
| `src/theme.ts`, `miniprogram/app.wxss` | Shared color, radius, and type tokens. Pages use the CSS variables; the share card imports the module. |
| `miniprogram/pages/report/` | One session report: 总览, then 问题, then 动作, plus 保存分享卡. The disclaimer leads the overview card and is drawn on the card. |
| `miniprogram/config.js` | API origin. |

`miniprogram/config.js` defaults to `http://127.0.0.1:8787`. Change `apiBaseUrl` for another machine. The value must start with `http://` or `https://`.

## Checks

From the repository root:

```bash
npm install
npm test
npm run typecheck
npm run smoke
```

`npm test` and `npm run smoke` in this package start the T2 server with the mock provider. They do not call a paid model. The smoke run checks three guest paths: one photo is blocked before any upload, two acceptable photos return a report whose disclaimer is the core text, and a poor side photo returns retake guidance without a report. `npm test` runs `check:emit`, which rebuilds `miniprogram/lib` and fails if those files differ from the commit.

## WeChat DevTools

Automated tests do not open the WeChat runtime. Use this pass before treating the UI as done.

1. Start the API from the repository root: `POSTURE_PROVIDER=mock npm start`. It listens on `127.0.0.1:8787`.
2. Build the page logic if `miniprogram/lib` is missing: `npm run build -w posture-miniprogram`.
3. In WeChat DevTools, import the `apps/weapp` directory. The project uses appid `touristappid` when you have no AppID.
4. In local settings, enable **不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**. The simulator can then call `http://127.0.0.1:8787`. A physical phone cannot use that loopback address; point `config.js` at an `https` origin that is on the mini program request allowlist.
5. Confirm the only pages are 体态自拍 and 训练参考. There is no history page and no login control.

Manual paths:

- On the front step, 下一步 stays unavailable until a front photo is chosen. The side slot is not on this screen. After a front photo, 下一步 opens the side step. 返回修改正面 comes back and keeps a side photo if one was already chosen.
- The side step does not open before a front photo is chosen. On that step, 开始分析 stays unavailable until the side photo is chosen. The bar says both photos are required.
- Choose a front photo and a side photo. 开始分析 opens 训练参考. The page reads 总览, then 问题, then 动作. The **非医疗诊断** heading and the disclaimer from the API are the first block of the overview card. Each problem is its own card, with matching cause guesses inside it. Actions follow, 3–5 cards.
- Choose a clear front photo and a tiny or blurry side photo. The side step shows 请重拍或补拍, the server summary, and the checklist. The report page does not open. If the result also names the front photo, the flow returns to the front step. Replace the photo and submit again.
- Leave the mini program, or tap 再测一次. The photos and the report are not listed anywhere afterward. Relaunching the mini program starts from an empty capture page.
- On 训练参考, tap 保存分享卡. The button draws the poster and asks to write it to the album. Allow the album prompt. The toast 已保存到相册 means the image is in the album; forward that image in a WeChat chat. The poster shows 非医疗诊断, the disclaimer text, the main problem, and the exercise tips. It does not show the two selfies. If album access was refused, tap 去设置, allow 保存到相册, then tap 保存分享卡 again. The album permission sheet does not clear the report. There is no share button on the capture page, and the report page does not enable 转发小程序.

The public platform privacy guide must allow writing to the album (`wx.saveImageToPhotosAlbum` / 相册（仅写入）), or the save call fails before an image is written.

Photos stay on WeChat temp paths until the request finishes or the guest removes them. The page deletes those temp files when a shot is replaced, when a report opens, and when the mini program hides. The share card is a separate temp PNG and is deleted after the album call finishes, including when the call is denied or fails. Nothing is written with `wx.setStorage` or `wx.saveFile`. Hiding caused by the camera, the album picker, or the share-card permission sheet does not drop the in-memory report.
